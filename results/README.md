# 模型测评成绩填写规则

[results.md](results.md) 是项目模型测评成绩总表。它回答哪个模型、哪个版本、在哪份数据上完成何种范围的测评、得到什么指标，以及模型代码与数据在哪里。

本目录跟踪人工核验后的成绩与必要小型摘要。训练日志、诊断过程和原始预测不放在这里；过程见 docs/stages，原始产物见 outputs。当前没有自动登记器，不自动扫描或同步任何外部目录。

## 收录条件

只登记完成约定范围、指标有效、通过完整性和适用协议验收、可追溯代码/模型/数据/指标来源的测评。
完整模型或系统的正式测评与辅助模块测评分表。对于分类等任务，固定测试集上的离线评测本身就是正式测评；辅助表指声明范围仅限某个模块，不能据此声称系统整体收益。

以下不进入成绩表：训练 loss 与训练过程、安装检查、单元测试、smoke、preflight、probe、fixture、补丁验证、执行失败或覆盖不完整的运行，以及未通过适用验收的结果。
低成绩、负增益或研究假设不成立不是排除理由；若结果有效并完成协议要求，应如实登记。完整性验收与研究收益目标应区分，不能通过后者筛掉有效负结果。

初始无结果时只写“当前尚无已登记测评结果”，不生成虚构模型、数据集、占位成绩或 full/not_run 行。

## 组织方式

总表以成绩表为主体，按数据集建立独立章节。章节内写明任务、split、语言等适用条件、测评协议、指标定义与单位；协议不同则进一步分组，不混合排名。

每个数据集下依次安排：

1. 正式测评成绩表。
2. 必要的有效样本与可比性说明。
3. 辅助模块测评表（存在此类成绩时才创建）。

末尾只保留简短的测评验证摘要与限制。详细运行、排错与修复过程链接阶段结论，不复制到总表。

## 正式测评表字段

| 字段 | 填写要求 |
|---|---|
| Record ID | 稳定且唯一，不复用；关联详情和原始证据 |
| Scope | full、固定子集或明确的累计范围，不用 full 代表非全量 |
| Samples | 实际完成且经完整性核验的样本数量；按项目可改为 Episodes 等单位 |
| Group | 方法所属分支或实验组；单项目也填写明确归属 |
| Model | 实际被测评的模型或方法名称 |
| Version | 精确版本、配置、checkpoint/adapter 标识；适用兼容补丁要明示 |
| Status | complete，或有明确定义的 complete/gate_pass；非合格运行不登记 |
| 各项实际指标 | 每项独立一列，列名标注单位与优劣方向，例如 Accuracy (%) ↑、RMSE ↓；不固定为某领域指标 |
| 适用的 Δ 指标 | 指明基线 Record ID，条件可比时填写，否则使用 — 并说明 |
| Benchmark SHA | 实际样本清单或数据版本清单的 SHA-256 |
| Model code path | 实际被测评代码的位置；配合版本与源码身份定位，不只填泛化仓库首页 |
| Dataset/manifest path | 实际数据或冻结测评清单位置，不仅写数据集名称 |

不同模型、版本和 scope 作为不同记录行；数据集等章节条件不得靠文件名猜测。
模型代码地址和数据地址必须在主表直接展示，不用一个结果详情链接替代。

Record ID 链接到同页证据条目或必要的单次详情；其中必须给出 artifact_path，以及配置、checkpoint 和实际源码身份。原始产物地址不替代 Model code path 与 Dataset/manifest path。
仓库内文件使用相对 Markdown 链接；外部资产记录真实 URI 或运行环境中的路径，并注明访问范围。没有访问权不等于路径不存在，无法核实时明确说明，不伪造证据链。

## 辅助模块测评

按模块目标选取各项指标，保留 Scope、Group、Model、Version、Status、样本数、代码与数据地址，并明确 claim_scope。
例如路由或检索模块的准确率、召回率不能替代完整系统指标。辅助表与对应数据集正式表分开，不做跨指标、跨范围的排行榜。

## 比较、聚合与有效性

- 不同数据集分别展示。不同 scope 可同表查看覆盖情况，不能直接宣称公平性能增量。
- 填写 Δ 前核对数据版本、split、语言、样本清单、预算、测评配置和指标口径，引用基线 Record ID。
- 百分比指标的绝对差用“百分点（pp）”；相对变化率须另行标明，二者不混用。
- 累计结果从样本结果按原指标定义聚合，不能默认平均分块汇总值。累计范围重叠要说明，不能当作独立重复实验。
- 如有非有限值或缺失，按 Record ID 列出计划数、实际覆盖、有效数、缺失/重复/失败/非有限数量及协议处理。不要静默删除失败样本。
- 多随机种子或重复测评注明次数、种子、均值与不确定性的具体定义；不能用单次结果伪装成重复统计。

## 来源与维护

官方代码标注需有可核查的来源、精确版本和必要差异检查。兼容补丁写入版本说明；checkpoint 的实际来源与校验状态单独记录。
引用论文成绩须明确“来源报告，非本项目实测”，单独列在参考说明，不当作本项目新测评行。固定子集不冒称论文全量结果。

登记前核对原始产物、模型、代码、数据清单与指标；更新实际更新时间及其时区。
同一运行不重复登记。更正已有成绩时保留旧值、原因、影响与依据，可放同页修订说明或关联详情；不抹去历史错误。
原始结果保留在所属 outputs 或授权产物位置，不为填写总表移动、覆盖或删除。登记测评数据不改变训练资格。

详细证据按需复制 [单次测评模板](../docs/templates/RESULT_TEMPLATE.md) 为本目录下以真实 Record ID 命名的详情文档。总表仍只有一份，不要求每次运行都新增长报告。
