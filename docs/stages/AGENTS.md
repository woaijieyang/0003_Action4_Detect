# 阶段文档规则

本文件适用于本目录及其阶段文档，细化 [根规则](../../AGENTS.md)，不扩大实验、资源或外部操作授权。用户当前明确要求优先。

## 一个阶段，一份计划和一份结论

阶段以用户确定的目标、范围和验收边界为准。同阶段最多一份 plan 和一份 conclusion；子任务、检查、失败、重试和修复在对应文档内集中维护。
不为每一天、每个子任务或一次验证创建重复报告。进行中的结论明确标注状态，不能写成最终完成。历史文件不因本规范自动改名、合并或移动。

## 命名与时间

使用 UTF-8 Markdown，名称为：
`YYYY-MM-DD-N-plan-主题.md` 或 `YYYY-MM-DD-N-conclusion-主题.md`。

日期使用用户指定时区，未指定时使用记录环境时区，并在正文注明。N 为当天 plan/conclusion 共用的正整数序号；读取当天已有规范文件，取最大序号加一，无文件时从 1 开始。
写入前再次检查重名，采用排他创建；并行冲突时重新读取清单和取号，不覆盖。主题自然、具体，不设机械字数限制。

跨日继续维护原文件，在正文记录实际更新时间和实验时间。未知时间明确写未记录，不用文件 mtime 替代。计划和结论互相链接。

## 计划至少覆盖

问题与证据、目标与交付、允许范围和停止边界、基线和输入身份、假设及实验设计、统一子任务顺序、资源和执行入口、可复核验收条件。
不是所有任务都需要实验；不适用项说明原因，不编造对照或样本数。
计划变化记录时间、原因、依据及对比较有效性的影响，不在看到结果后悄悄改写原标准。

## 结论至少覆盖

阶段身份与实际状态、对应计划、各子任务实际执行过程、计划偏差、失败和修正、真实验证结果、证据位置、验收逐项对应、限制与未完成项。
事实、推断与研究结论分开；离线组件检查、工程测试和完整模型测评分别标明。保留有判断价值的负结果和失败历史，纠错说明原错误与影响。

## 记录位置

本目录放阶段计划与结论。原始输出保留 outputs，成绩汇总到根 [results](../../results/results.md)，Git 事务概述记 [README_WORKFLOW](../../README_WORKFLOW.md)。
不复制大日志、模型回答、权重、数据或逐样本预测进入文档；只记录必要事实和稳定引用。
可用 [计划模板](../templates/PLAN_TEMPLATE.md) 与 [结论模板](../templates/CONCLUSION_TEMPLATE.md)，模板本身不是已执行任务。
