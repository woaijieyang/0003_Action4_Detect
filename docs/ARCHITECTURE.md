# 架构与扩展边界

本模板按数据准备、模型实现和模型测评分工。目录结构不等于功能已经实现；当前仅包含三个可安装的空包。

## 依赖方向

```text
scripts -> eval / model / data
eval -> model / data
model/training -> model / data
data -> 通用依赖
```

model 主体不依赖 eval；data 不导入模型或测评业务。跨模块状态通过所属模块正式接口修改，不维护重复权威状态。

## 放置判断

| 工作 | 位置 | 原因 |
|---|---|---|
| 清洗、格式转换、划分与数据集封装 | src/data | 属于输入数据的准备和解释 |
| 可学习编码器、网络层与方法算法 | src/model | 属于模型方法 |
| 训练循环、损失及优化逻辑 | src/model/training（按需） | 属于模型训练 |
| 测评模型选择、加载与设备设置 | src/eval | 属于测评生命周期 |
| 模型结构及自身状态接口 | src/model | 训练与测评共同使用 |
| 模拟或其他测评环境初始化 | src/eval | 为测评协议服务 |
| 指标计算、有效性校验和聚合 | src/eval | 属于测评定义 |
| 参数解析和启动 | scripts | 复用正式实现的薄入口 |

通用归一化、格式转换归 data；方法特有的可学习变换归 model。命名相同不意味着职责相同，应根据是否属于方法及实际依赖判断。
遇到三部分都需要的代码，先明确其真实责任；没有已验证的复用需求时不新增宽泛的 utils/common 框架。

## 代码、资产与证据

src/data 与根 data 分别是代码和资产；src/model 与根 models 分别是代码和权重。
根 data、models、outputs、runtime、upstream 已预建，各自 README 进入 Git 以保留目录；其余实际文件及子目录默认忽略。工具生成的 .cache 与 .venv 不预建。
outputs 保存原始运行产物，results 保存测评成绩索引，docs 保存工程与阶段说明。
运行环境放 .venv 或 runtime，缓存放 .cache；不嵌入源码包。第三方副本放 upstream；必要兼容补丁随真实需要增加，并记录来源和固定版本。

测评答案由计分器使用；训练标签按训练协议使用。共享数据只读，不通过路径或软链混入可写输出。
改变接口时同步调用方、测试和目录说明；不以目录调整为由扩大模型行为或测评协议。

## 新项目使用顺序

更新项目元数据和入口 README；明确数据与模型来源及许可；根据实际工作增加配置、实现、入口和对应验证。
长期规则维护在 [AGENTS](../AGENTS.md)，阶段范围维护在 [阶段计划](templates/PLAN_TEMPLATE.md) 中。
本模板不固定资源数量、主机、云服务、索引工具或训练框架。
