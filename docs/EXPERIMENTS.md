# 运行身份与实验规范

本文件规定如何保存可复核证据。训练、测评、下载、外部调用和资源使用依当前任务授权，不因本文或历史计划获得许可。

## 开始之前

在阶段计划中确定问题、基线、变量、样本范围、预算、种子、评测协议、验收与停止条件。
核对资源归属和可用性，不终止其他任务进程；缺少必要信息时不得自动扩大规模或把预检当正式测评。
复用现有已授权数据与模型。共享原始输入只读，派生结果写入任务自有位置。

## 每次运行的身份

使用独立且不复用的 run_id，新尝试创建新目录，不覆盖旧运行。
运行记录至少包含：

| 信息 | 要求 |
|---|---|
| 时间与状态 | 实际起止时间及其时区；计划、运行、完成、失败等状态如实记录 |
| 代码 | commit（如有）、工作树是否有改动、实际参与运行的源码快照或哈希 |
| 配置 | 最终生效配置、覆盖项、预算、设备与必要校验值 |
| 模型 | 名称、实际 checkpoint/adapter、来源、版本和校验状态 |
| 数据 | 版本、split、样本清单、清单哈希、划分和使用限制 |
| 执行 | 入口命令、解释器和依赖身份、随机种子、资源及实际调用范围 |
| 产物 | 原始结果、日志和汇总的真实位置；有效、缺失、失败与重复数量 |

Git HEAD 不是有改动工作树的完整身份。运行期间源码或协议变化需形成可区分的新身份，不能用新版本解释旧结果。

## 输出目录约定

以下是实现运行器时采用的命名约定，不是已经存在的生成器：

```text
outputs/<run_id>/
  run_manifest.json       本次身份、状态和产物索引
  resolved_config.json    最终生效配置（可用项目已选定格式）
  predictions.jsonl       逐样本原始输出，格式依项目协议
  metrics.json            汇总指标、分母和有效性信息
  logs/                   运行日志
```

仅创建运行实际需要的文件。原始输出不能被汇总表替代；日志不能包含密钥，分享证据前检查数据权限和隐私。
项目自有派生数据可以保存于根 data/processed，权重保存于根 models；manifest 引用实际路径，避免重复复制大资产。

## 协议与验证

- 训练、验证和测试的用途分开，标记已参与调参或选择的数据。评测登记不自动授予训练资格。
- 保留失败样本与尝试；重试或替换必须遵守预先协议，不自动修补模型答案。
- 数据覆盖核对清单身份、重复、缺失与非有限值。聚合按指标定义执行，不能默认平均分块指标。
- 比较时固定应相同的条件，记录基线和变量。未通过完整性检查的运行不形成正式成绩。
- 静态检查、工程测试、组件指标、完整测评与研究收益分别说明；接口可用不代表模型有效。

## 写入成绩与保留证据

按 [结果规则](../results/README.md) 将合格成绩登记至 [results.md](../results/results.md)，每条用 Record ID 关联代码、数据和原始产物。失败与过程写入阶段结论，原始文件保持原位。
必要时使用 [单次测评详情模板](templates/RESULT_TEMPLATE.md)；不要同时维护多个互相冲突的成绩总表。
用户未授权清理前保留原始证据。归档与删除属于另行确认范围，不能因 Git 忽略或总表已生成便自动清除。
